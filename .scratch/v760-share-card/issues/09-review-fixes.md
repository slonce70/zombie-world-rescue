# 09 — Виправлення за рев'ю v760

**What to build:** рев'ю релізу знайшло три речі навколо листівки. Перші дві блокують деплой.

## (а) Мовчазна кнопка — `src/ui/share.js:34`

```js
export async function shareImageFile(game, blob, { ... } = {}) {
  if (!blob) return 'failed';        // ← жодного тоста
  ...
  game.hud.toast(t('😕 Не вдалося зберегти картинку'));  // сюди вже не дійде
```

`cardBlob` (`src/ui/sharecard.js:146`) резолвиться в `null` при будь-якому фейлі `toBlob` —
брак пам'яті під канвас 1080×1080 на слабкому планшеті, старий WebView. Тоді дитина тисне
«📸 Похвалитися», кнопка на мить сіріє і **нічого не відбувається**.

Мовчазна мертва кнопка в дитячій грі — найгірший вид відмови, а тост для цього вже
написаний рядком нижче.

## (б) iOS втрачає жест користувача через `await` — `src/ui/sharecard.js:154`

```js
const blob = await cardBlob(drawCard(card));   // ← тут губиться transient activation
return shareImageFile(game, blob, {...});      // → await navigator.share(...)
```

Safari на iPhone вимагає, щоб `navigator.share()` викликався в тому ж таску, що й жест.
Після `await` він кидає `NotAllowedError`, код це коректно ловить і падає у фолбек — але
фолбек на iPhone означає «картинка впала у Файли» замість системного вікна «надіслати
в месенджер». Тобто головна цінність релізу не спрацює саме на телефоні.

Треба готувати картинку **заздалегідь** — коли показується екран перемоги (і коли
відкривається кімната), щоб на момент тапу blob уже existував і `navigator.share()`
викликався одразу після жесту.

## (в) Канвас перемоги висить у пам'яті — `src/ui/endscreens.js:86,259`

`game._victoryCard.frame` — канвас 1080×1080 (~4.4 МБ) не звільняється при виході з екрана
перемоги, лише перезаписується наступного разу. Скинути в `null`, коли екран закривається.
