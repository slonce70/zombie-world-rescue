# 11 — Драфт відкриває меню паузи під собою, а магазин забирає в нього керування

**What to build:** два боки однієї проблеми — драфт не врахований у гейтах керування.

**(а)** `Draft.open()` кличе `input.exitLock()` → подія `pointerlockchange` →
`onLockChange(false)` → `showPause()`, бо в умові (`src/main.js:338-345`) перевіряються
`shop.isOpen` і `_chestState`, але **не** `draft.isOpen`. Еталон правильного гейта —
`src/rewards.js:455`.

Відтворення: соло-кампанія на десктопі → здати місію → драфт відкривається, під ним
показане меню паузи; після вибору картки гру треба знімати з паузи вручну.

**(б)** `KeyB` (`src/main.js:362`) не заблокований при відкритому драфті, а `Shop.close()`
(`src/shop.js:183`) робить `input.request()` — pointer lock повертається і перехоплює кліки
по картках драфту. Той самий симптом уже описаний у коментарі `src/rewards.js:379`.

Відтворення: при відкритому драфті натиснути `B`, потім `B`/`Esc` — картки не клікаються,
рятує лише повторний `Esc`.

Заразом дрібниця з того ж модуля: `Draft.pick(idx)` (`src/draft.js:51-57`) з невалідним
індексом скидає `_expire`, але лишає `isOpen = true` і клас `.show` — симуляція
заморожується назавжди.

**Blocked by:** None — can start immediately.
